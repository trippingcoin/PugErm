План создания веб-платформы/дашборда для скоринга сельхозпроизводителей

Цель: создать веб-платформу, которая принимает данные, строит ML‑скоринг заявителей, объясняет итоговый score и формирует shortlist для комиссии.

1. Сбор и понимание данных
- Подтвердить перечень файлов из предоставленного датасета и форматы.
- Зафиксировать целевую переменную (если есть историческое решение/эффективность субсидий) и критерии качества.
- Описать доступные признаки: история субсидий, характеристики хозяйства, показатели деятельности.

2. Предобработка и фичи
- Очистка пропусков, дубликатов, выбросов.
- Нормализация/кодирование категориальных признаков.
- Формирование производных признаков (динамика урожайности, эффективность использования субсидий, стабильность показателей).
- Разделение на train/valid/test по времени (если есть временной аспект).

3. ML‑модель скоринга
- Базовый скоринг: градиентный бустинг (CatBoost/LightGBM) или интерпретируемая модель (Logistic/Explainable Boosting) в зависимости от качества.
- Калибровка score в шкалу 0–100.
- Метрики: ROC-AUC, PR-AUC, calibration, stability.

4. Explainability (обязательно)
- Глобальная интерпретация: важность признаков.
- Локальная интерпретация: SHAP/feature contributions для каждого заявителя.
- Краткое текстовое объяснение: топ‑3 фактора, повлиявших на score.

5. Shortlist и рекомендации
- Правила отбора (например, top‑N по score + фильтры риска).
- Отдельный блок для комиссии: список кандидатов, score, объяснение, ключевые показатели.

6. Веб‑архитектура
- Backend: сервис приема данных (CSV/XLSX), запуск пайплайна, хранение результатов.
- Model service: загрузка модели, инференс, explainability.
- Frontend: дашборд с загрузкой данных, визуализацией скоринга, фильтрами и карточкой заявителя.

7. UX дашборда
- Главная панель: распределение score, топ‑факторы, динамика по регионам/типам хозяйств.
- Таблица заявителей с сортировкой, поиском, фильтрами.
- Карточка заявителя: score, объяснение, история субсидий, ключевые показатели.
- Экспорт shortlist в CSV/PDF.

8. Качество и контроль
- Валидация входных данных и логирование.
- Мониторинг качества модели и дрейфа.
- Аудит решений (лог объяснений и версии модели).

9. Документация и запуск
- README: инструкция по запуску, формат входных данных.
- Техническое описание модели и объяснений.
- Демонстрационный набор данных и примеры.
