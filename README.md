# PugErm

PugErm — прототип для Case 2 хакатона Decentrathon 5.0: скоринг заявок сельхозпроизводителей на получение субсидий с объяснением результата.

Система помогает комиссии:
- принять XLSX или CSV с заявками,
- рассчитать score для каждой записи,
- показать факторы, повлиявшие на результат,
- сформировать shortlist кандидатов для ручного рассмотрения.

Важно: прототип не заменяет эксперта и не принимает окончательное решение автоматически.

## Что входит в Stage 1

В репозитории уже есть минимально рабочий элемент для первого этапа:
- веб-интерфейс для загрузки файла и просмотра результатов,
- backend на FastAPI,
- ML-скрипт для ранжирования заявок и объяснения score.

## Структура репозитория

- `cmd/server/main.py` — сервер и API
- `ml/score.py` — пайплайн скоринга и explainability
- `web/` — фронтенд
- `Data.xlsx` — демонстрационный датасет для локальной проверки
- `PLAN.md` — план развития решения
- `ARCHITECTURE.md` — описание архитектуры решения

## Какие данные используются

Основной демонстрационный файл:
- `Data.xlsx`

В текущем демо-файле используются поля:
- область,
- акимат,
- направление субсидирования,
- наименование субсидирования,
- статус заявки,
- норматив,
- причитающая сумма,
- район хозяйства.

Технические поля вроде номера строки, номера заявки и даты поступления автоматически исключаются из скоринга, чтобы не искажать результат.

## Как работает прототип

Пайплайн выполняет следующие шаги:
1. загружает XLSX или CSV;
2. очищает полностью пустые строки и столбцы;
3. исключает технические поля и идентификаторы;
4. кодирует числовые и категориальные признаки;
5. если есть корректная целевая колонка, запускает supervised-режим;
6. если целевой колонки нет, строит prototype ranking в unsupervised-режиме;
7. возвращает shortlist, score и объяснение факторов для каждой записи.

Explainability реализован в двух формах:
- глобальные факторы, влияющие на ранжирование,
- локальные факторы для каждой конкретной заявки.

## Ограничения текущей версии

- Текущий `Data.xlsx` больше похож на набор заявок, чем на полноценный датасет эффективности производителей.
- В демонстрационной версии может использоваться unsupervised ranking, если нет надёжной target-колонки.
- Прототип пока не использует полную историю предыдущих субсидий и производственных результатов хозяйства.
- В проекте пока нет постоянного хранилища, логирования аудита и пользовательских ролей.
- На больших файлах обработка может занимать заметное время.

## Локальный запуск

Создать виртуальное окружение и установить зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r ml/requirements.txt
```

Запустить приложение:

```bash
python3 cmd/server/main.py
```

Открыть в браузере:

```text
http://localhost:8080
```

## Быстрая проверка

### Проверка через CLI

```bash
source .venv/bin/activate
python3 ml/score.py --input Data.xlsx --shortlist 3
```

Ожидаемый результат:
- в stdout возвращается JSON,
- в ответе есть блоки `meta`, `global_factors`, `records`, `shortlist`.

### Проверка через UI

1. Открыть `http://localhost:8080`
2. Оставить настройки по умолчанию
3. Нажать `Использовать Data.xlsx`
4. Дождаться появления сводки, факторов, shortlist и таблицы

## API

### `POST /api/score`

Опциональные query-параметры:
- `target` — имя target-колонки для supervised-режима
- `id` — имя колонки идентификатора
- `shortlist` — размер shortlist

Опциональное поле multipart-запроса:
- `file` — загружаемый `.xlsx` или `.csv`

Пример:

```bash
curl -X POST "http://localhost:8080/api/score?shortlist=5"
```

## Практическая ценность

Прототип показывает, как перейти от модели "кто первым подал документы" к модели приоритизации заявок на основе данных и объяснимого скоринга.

Это полезно для:
- комиссий, рассматривающих заявки,
- аналитиков министерства,
- сотрудников госорганов, которым нужен прозрачный shortlist с объяснением.
